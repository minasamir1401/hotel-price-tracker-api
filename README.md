# مقارنة أسعار الفنادق

واجهة React بالعربية على `http://localhost:5173/` وخادم Node على المنفذ 5000. الاتصال الحي يعمل مع المسافر والمطار. لا تستخدم المحركات أسعارًا حسابية أو تجريبية.

## قواعد الأسعار والمطابقة

- يستعلم عن كل ليلة مستقلة بالتاريخ ومعرّف الفندق وعدد الغرف والبالغين وأعمار الأطفال. لا توجد أسعار ثابتة أو بدائل تجريبية أو نسخ لسعر يوم آخر.
- المسافر يجلب `APIToken` الحالي من بيانات صفحة الفندق الرسمية ويشارك تهيئة الجلسة بين الطلبات لمدة 5 دقائق. طلبات الأسعار لا ترسل `general-key` بقيمة افتراضية، لأن هذه القيمة تغيّر مجموعة عروض الموردين؛ فحص كينجزجيت يوم 20 أكتوبر أرجع 807.66 بدونها و936.09 معها. يمكن تحديد توكن صريح عبر `ALMOSAFER_API_TOKEN` عند الحاجة. تحفظ العروض معرّف المورد والعقد مع معرّف الباقة لتدقيق السعر.
- الرد الفارغ لا يؤكد عدم التوفر إلا إذا رجع الفندق الصحيح والعملة ومدة الليلة وبنية العروض. نتائج `no-pkg` دون هوية الفندق أو الردود الناقصة تعاد بجلسة جديدة، وتظهر «تعذر التحقق» إذا بقيت غير مؤكدة؛ لا تتحول إلى «لا توجد غرفة متاحة» ولا تستعير سعر يوم آخر. زر «إعادة التحقق» يجلب ليلة واحدة لنفس الفندق والغرفة والإشغال، ويحدث الجدول والإجماليات وExcel من عرض المصدر الجديد فقط.
- ينتظر اكتمال عروض المصدر. يعيد الاستعلام الفارغ أو الفاشل مرة، بمهلة جديدة 45 ثانية لكل محاولة. بعد جمع الأيام يعيد فحص كل الأيام الفارغة والفاشلة بتزامن أقل. فشل الاتصال يظهر «تعذر التحقق»، وغياب عرض فعلي يظهر «غير متاح».
- اختيار عدد ونوع السراير يعتمد على وصف السراير الصريح في المصدر، وليس عدد النزلاء أو كلمة Double. الغرف غير محددة السراير مستبعدة من البحث الدقيق، ويمكن إظهارها صراحة كمطابقة غير مؤكدة.
- تُجمع العروض ذات اسم الغرفة والسراير والإطلالة الصريحة نفسها رغم تغير معرّف المورد بين الأيام. عند غياب وصف السراير تبقى هويات المورد منفصلة لتجنب خلط غرف مختلفة أو إسناد فطور غرفة إلى أخرى.
- أسماء الغرف والوجبات تأتي من المصدر: «إقامة فقط»، «إقامة وفطور»، «وجبتان». تظهر أعمدة الإلغاء المجاني فقط عند وجود عروض فعلية بهذه السياسة. لا تستخدم الواجهة أو Excel تسمية «أقل سعر».
- اختيار الغرفة يحدد الجدول والإجماليات وExcel. لا يظهر مجموع كامل إلا عند توفر الخطة في جميع الليالي. المجموع يجمع الأسعار الفعلية، ولا يضرب متوسطًا مقربًا.
- الأسعار مجموع حجوزات ليلة واحدة مستقلة، وقد تختلف عن حجز إقامة متصلة. صورة تاريخية لغرفة بسريرين لا تثبت أن عرض Double Room العام هو نفس الغرفة.
- كاش النتائج المكتملة دقيقتان والفارغة 20 ثانية، والفشل لا يُخزن. زر البحث يجدد الأسعار.

## اتصال المطار

يستخدم مسار الويب الرسمي `https://almatar.com/api/hotel/v5/rooms/getpackages/search_with_hotel` ويستكمل العروض غير المكتملة بمسار v4 الخاص بالجلسة. يُتحقق من هوية الفندق من خدمة `hotelbyprofilekey` ومن التواريخ والإشغال والعملة في كل رد. اسم الفندق والغرف والسراير وسياسة الإلغاء والوجبات تأتي من الرد الفعلي. يتطلب البحث رابط صفحة الغرف من المطار، لأن معرّفات الفنادق تختلف بين المنصتين.

المطار يعرض إجمالي الباقة مقربًا للأعلى إلى ريال كامل؛ تتبع الأسعار هذه القاعدة قبل تقسيم إجمالي الباقة على عدد الغرف. السعر يتضمن الخصم الذي أرجعه المصدر، بدون اختلاق نسبة خصم. تحفظ العروض أيضًا قيمة المصدر قبل التقريب وكود الخصم الفعلي. أسماء الوجبات الخاصة به مثل «إقامة وإفطار» و«إفطار + غداء أو عشاء» محفوظة في الواجهة وExcel.

إذا فشل مصدر ونجح الآخر، تبقى النتائج الناجحة مع بيان الفشل. اختيار الغرفة يحدد المصدر وأسماء وجباته ورابطه في الجدول والتصدير.

## التشغيل والتحقق

في `backend`: `npm run dev`. في `frontend`: `npm run dev`.

`npm test` داخل كل من `backend` و`frontend`، ثم `npm run build` داخل `frontend`. إعداد Vite يستخدم `--configLoader native` لتجنب خطأ تحميل Tailwind على Windows.

تشمل الاختبارات استقلال الأيام والغرف، عدم اختلاق الوجبات الناقصة، اكتمال الاستعلام، تجدد مهلة المحاولة، إصلاح الأيام الفارغة والفاشلة، مطابقة السراير، تغير معرّف المورد، دقة الإجماليات ومطابقة تصدير Excel.

`node backend/verify-month-live.js` يفحص أكتوبر 2026 مباشرة ويكتب النتائج في `backend/verification`؛ الأسعار والتوفر قابلان للتغير.

`node backend/verify-october-matrix.js` يفحص 3 فنادق من كل مصدر، من 1 أكتوبر إلى 31 أكتوبر 2026، في 3 حالات: غرفة لبالغ، غرفة لبالغين، وغرفتان لبالغين في كل غرفة (إجمالي 4). يحفظ طلبات وردود المصدر، ويربط كل سعر بمعرّف الباقة، ويتحقق من هوية الفندق والتاريخ والإشغال والإجماليات، ثم يعيد قراءة ملفات Excel الناتجة من نفس مُصدّر الموقع لكل غرفة قابلة للاختيار. النتائج في `outputs/october-2026-live`.

استخدم `--resume` لاستكمال الحالات الناقصة وإعادة فحص اللقطة المحفوظة، أو `--reconcile-only` لمراجعتها بدون استعلامات جديدة. يحافظ التصدير على الغرف والبالغين لكل غرفة والإجمالي، وتختلف أسماء الملفات حسب الإشغال. اختبار `node backend/verify-http-occupancy.js` يراجع الحالات الست للمصدرين عبر مسار API الفعلي للواجهة على المنفذ 5173.

## API

`POST /api/search-hotel-prices` يقبل `hotelInput`, `checkIn`, `checkOut`, `adults`, `children`, `childAges`, `rooms`, `sources`, `refresh`, `bedCount`, `bedType`, `includeUnknownBeds`.

`bedCount`: صفر لأي عدد، أو 1–8. `bedType`: `any`, `single`, `double`, `king`, `queen`. الافتراضي يستبعد السراير غير المؤكدة عند تفعيل الفلتر.

النتيجة تحتوي `data` للغرف، `dailyRates` لكل التواريخ، `summary` و`warnings`. الأسعار المفقودة `null`؛ لا تُعامل كصفر.

`GET /health` لفحص الخادم فقط. `GET /api/system-status` يعرض آخر نتيجة اتصال لكل مصدر: `unchecked` قبل التحقق، `ready` بعد رد أسعار مكتمل، `blocked` عند رفض 403، و`error` عند فشل آخر. النجاح الأقدم من خمس دقائق يعود إلى `unchecked`.

## إصلاح اتصال المسافر على Dokploy

روابط `global.almosafer.com` تستخدم جلسة وطلبات أسعار على دومين `global` نفسه؛ روابط `www` تستخدم `www`. لا تُشارك الكوكيز أو نتائج الكاش بين الدومينين. يمكن ضبط `ALMOSAFER_ORIGIN` على أحد الدومينين عند البحث باسم الفندق أو رقمه. لا ينتقل العميل تلقائيًا إلى دومين آخر عند رفض الوصول.

يستخدم جلب الغرف والبحث نفس عميل المسافر الذي يهيئ جلسة ويب حديثة ويجددها عند رفض الاعتماد. أُزيل التوكن الثابت الافتراضي؛ اترك `ALMOSAFER_API_TOKEN` فارغًا عادةً. لا يتم استخدام توكن قديم عند فشل تهيئة الجلسة، ولا يُعرض فشل الاتصال على أنه نفاد غرف.

عند استمرار الرفض بعد إعادة نشر الباك، ابحث في Logs عن `[UPSTREAM FAILURE]` ومعرّف `diagnosticId` الظاهر في الواجهة. السجل يحدد المرحلة (`session-bootstrap`, `packages`, `poll`)، كود المصدر، نوع الرفض وبعض هيدرز الرد الآمنة؛ لا يسجل توكنات أو كوكيز أو جسم الرد. `access-denied` دليل رفض الوصول، لكنه لا يثبت حظر IP وحده. لا يمكن للتطبيق ضمان قبول المصدر لكل عنوان سيرفر.

الفرونت في مستودع `hotel-price-tracker`، والباك في `hotel-price-tracker-api`؛ يلزم إعادة نشر الخدمتين لتطبيق التعديلات معًا. طلب الغرف يؤكد الليلة الأولى المطلوبة فقط ويشمل كل الغرف وأعمار الأطفال؛ لا ينتقل تلقائيًا إلى تواريخ أخرى. الواجهة تؤخر طلب الغرف حتى استقرار الإدخال، وتلغي النتائج القديمة عند تغيير الفندق أو الإشغال.

مصدر Booking يعمل عبر API التطبيق بدون جهاز أندرويد أو محاكي. إعداداته وحدود التغطية في `backend/BOOKING.md`. قيم تعريف التطبيق تُضبط كمتغيرات خاصة بالباك ولا تُرفع إلى GitHub.

## غرفة المروة ريحان الظاهرة في الصور

تفتح الواجهة على أكتوبر 2026، غرفة واسعة بسرير توأم، بالغين اثنين وغرفة واحدة. يعرض الجدول وتصدير Excel دائمًا «إقامة فقط»، «إقامة وإفطار»، و«إفطار + غداء أو عشاء»، مع «غير متاح» للخطط التي لا يرجعها المصدر. تعرض لقطة الاستعلام المكتملة المحفوظة مع وقت جلبها؛ زر البحث يجلب أسعارًا جديدة. اللقطة ليست أسعار الصور التاريخية.

مسار `POST /api/daily-prices` يستخدم محرك المطار نفسه مع التحقق من الفندق والتاريخ والإشغال واكتمال البحث. يقبل `roomName` للمطابقة الكاملة، و`bedCount`, `bedType`, `mealPlan`, `rooms` بالإضافة إلى حقول الفترة والنزلاء. يحتفظ كل سعر بمعرّف الباقة وقيمة المصدر قبل التقريب. سياسة الإلغاء تخص الباقة التي جاء منها السعر المعروض، وليست حالة أي باقة أخرى لذلك اليوم.

لتحديث لقطة أكتوبر مع حفظ الطلبات والردود: `node backend/fetch-almarwa-october.js` من جذر المشروع. ملفات التدقيق في `outputs/almarwa-october-2026`، ولقطة الواجهة في `frontend/public/almarwa-october-2026.json`. للتحقق من ربط كل سعر بباقة المصدر ثم اختبار المسار الفعلي عبر Vite: `node backend/verify-almarwa-result.js` بعد تشغيل الخادم والواجهة.

عند منع Windows تشغيل `node --watch`، يمكن تشغيل الباك مباشرة باستخدام `node server.js` داخل `backend`.
